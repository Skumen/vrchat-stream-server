# VRChat Stream Server

Свой стрим-сервер для видеоплееров VRChat. OBS отправляет поток на сервер, а сервер раздаёт его сразу в трёх форматах, чтобы у каждого зрителя была рабочая ссылка:

```
                          ┌─ RTSP  rtspt://…:8554/live/stream  → VRChat PC            ~1 с
OBS ──RTMP:1935──▶ MediaMTX ┼─ RTMP  rtmp://…/live/stream        → VRChat PC (запасной) ~1–2 с
                          └─ HLS ─▶ nginx :80/:443 ─▶ …/live/stream/index.m3u8
                                                              → PC + Quest/Android  ~3–5 с
```

- **[MediaMTX](https://github.com/bluenviron/mediamtx)** принимает поток от OBS и раздаёт его по RTSP, RTMP и HLS без перекодирования, поэтому почти не нагружает процессор.
- **nginx** раздаёт HLS наружу по HTTP и HTTPS и получает сертификат Let's Encrypt.

## Быстрая установка

На VM с Ubuntu 20.04+ или Debian 11+ (x86_64 или ARM) выполните:

```bash
curl -fsSL https://raw.githubusercontent.com/Skumen/vrchat-stream-server/main/setup.sh -o setup.sh
sudo DOMAIN=stream.example.com bash setup.sh
```

Замените `stream.example.com` на свой домен. Если домена нет, запустите просто `sudo bash setup.sh`: сервер будет работать по HTTP.

Через несколько минут скрипт выведет готовые настройки для OBS и ссылки для VRChat. Дальше откройте порты (см. ниже) и настройте OBS по [OBS-settings.md](OBS-settings.md).

## Установка подробно

Скрипт можно скачать командой выше или скопировать на VM вручную. Запуск без HTTPS:

```bash
sudo bash setup.sh
```

С HTTPS (рекомендуется, так надёжнее для Quest). Нужен домен, A-запись которого указывает на сервер:

```bash
sudo DOMAIN=stream.example.com bash setup.sh
```

Бесплатный домен можно взять, например, на [DuckDNS](https://www.duckdns.org). Сертификат продлевается автоматически. Почту указывать не обязательно: `EMAIL=you@example.com` только привяжет её к аккаунту Let's Encrypt.

В конце скрипт выведет готовые настройки для OBS и ссылки для VRChat. Потом их можно вывести снова командой `sudo vrc-stream info`.

**Порты.** Если VM в облаке, откройте в панели провайдера (security group / firewall) входящие **TCP 80, 443, 1935, 8554**. Правила `ufw` скрипт добавит сам, если ufw включён.

Скрипт можно запускать повторно. Он сам уберёт старую установку на `nginx-rtmp` (блок `rtmp{}`, `SK.conf`, tmpfs) и сохранит бэкап `/etc/nginx` в `/root/vrc-stream-backups/`.

**Обновление до свежей версии из репозитория.** Скачайте скрипт той же командой `curl` и запустите `sudo bash setup.sh`. Сохранённые настройки (ключ, домен и т.д.) останутся.

## Настройка OBS

> Полная инструкция с профилями качества, настройками для NVIDIA/AMD/Intel/x264 и решением проблем — в [OBS-settings.md](OBS-settings.md).

**Настройки → Трансляция**
- Сервис: *Настраиваемый…*
- Сервер: `rtmp://<ваш сервер>/live`
- Ключ потока: `stream?user=obs&pass=<ключ>` (строку целиком выводит `sudo vrc-stream info`)

**Настройки → Вывод** (режим *Расширенный*)

| Параметр | Значение |
|---|---|
| Кодировщик | **H.264**: NVENC / AMF / QuickSync / x264. HEVC и AV1 не подходят, их не воспроизводит Quest |
| Управление битрейтом | CBR |
| Битрейт | 3000–4500 Кбит/с для 720p, 4500–6000 для 1080p |
| **Интервал ключевых кадров** | **1 с** (равен `HLS_SEGMENT`; при `HLS_SEGMENT=2s` ставьте 2) |
| B-кадры | 0 |
| x264: Tune | zerolatency |
| Аудио | AAC, 160 Кбит/с, **48 кГц**, стерео |

**Видео:** 1920×1080 или 1280×720, 30 fps. Для Quest надёжнее 720p30.

## Ссылки для VRChat

| Ссылка | Кто может смотреть | Задержка |
|---|---|---|
| `https://<домен>/live/stream/index.m3u8` | **Все**: PC, Quest, Android | ~3–5 с |
| `rtspt://<сервер>:8554/live/stream` | Только PC | ~1 с |
| `rtmp://<сервер>/live/stream` | Только PC (запасной вариант) | ~1–2 с |

- Если в мире смешанная аудитория (PC + Quest), ставьте в плеер **HLS-ссылку**, её видят все.
- Если смотрят только с PC и важна синхронность (музыка, реакции на чат), используйте `rtspt://`.
- Нужен плеер на **AVPro**: ProTV, iwaSync3 (режим LIVE), USharpVideo (Stream). Unity-плеер трансляции не показывает.
- **Каждый зритель должен включить «Allow Untrusted URLs»** (Settings → Comfort & Safety). Ваш сервер не входит в белый список VRChat, и без этой настройки ссылка не откроется.
- Проверить поток без VRChat можно в браузере (`https://<домен>/live/stream/`) или в VLC (*Медиа → Открыть URL*).

## Управление

```bash
sudo vrc-stream info       # настройки OBS и ссылки
sudo vrc-stream status     # идёт ли эфир, дорожки, битрейт, число зрителей
sudo vrc-stream logs       # логи MediaMTX в реальном времени
sudo vrc-stream restart    # перезапуск
sudo vrc-stream new-key    # новый ключ для OBS (если старый утёк)
sudo vrc-stream install    # применить новые настройки / обновить
sudo vrc-stream uninstall  # удалить
```

## Настройки

Настройки передаются переменными при установке и запоминаются в `/etc/vrc-stream/settings.env`. Пример: `sudo HLS_SEGMENT=2s vrc-stream install`.

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `DOMAIN` | — | Включает HTTPS через Let's Encrypt. `DOMAIN=` выключает HTTPS |
| `EMAIL` | — | Необязательно: почта для аккаунта Let's Encrypt |
| `STREAM_KEY` | случайный | Пароль для OBS |
| `HLS_SEGMENT` | `1s` | Длина HLS-сегмента. `2s`: задержка ~6 с, но меньше подгрузок у зрителей со слабым интернетом |
| `OFFLINE_SCREEN` | `1` | Заставка, пока OBS не в эфире (см. ниже). `0` выключает |
| `HLS_VARIANT` | `mpegts` | `mpegts` — максимальная совместимость. `fmp4` и `lowLatency` — эксперименты |
| `PUBLIC_HOST` | авто | Адрес сервера в ссылках, если автоопределение IP ошиблось |
| `RTMP_PORT`, `RTSP_PORT` | `1935`, `8554` | Порты |

### Заставка вместо обрыва (включена по умолчанию)

Пока OBS не в эфире, сервер показывает заставку «STREAM IS OFFLINE». Плееры зрителей остаются подключёнными, поэтому после старта или перезапуска OBS картинка появляется сама, без перезапуска видео.

**Условие:** в OBS должны быть H.264 и аудио **AAC 48 кГц стерео** (это значения OBS по умолчанию). Если выставлено 44.1 кГц, сервер откажет OBS в подключении. Причину покажет `sudo vrc-stream logs` (`audio configuration does not match`). Выключить заставку: `sudo OFFLINE_SCREEN=0 vrc-stream install`.

## Нагрузка

Каждый зритель скачивает поток целиком, поэтому исходящий трафик ≈ битрейт × число зрителей. Например, 5 Мбит/с × 40 зрителей ≈ 200 Мбит/с. Процессор почти не нагружается, узкое место — канал VM.

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| OBS не подключается | `sudo vrc-stream logs`: `authentication failed` — неверный ключ; `audio configuration does not match` — в OBS аудио 44.1 кГц, нужно 48 кГц (Настройки → Аудио → Частота дискретизации). Порт 1935 должен быть открыт у провайдера |
| Не грузит ни у кого | `sudo vrc-stream status`: идёт ли эфир. Порты 80/443 открыты? Ссылка открывается в браузере? |
| Не грузит у части зрителей | У них не включено «Allow Untrusted URLs» |
| Работает на PC, не работает на Quest | Для Quest используйте HLS-ссылку (не `rtspt://` и не `rtmp://`), лучше с HTTPS. В OBS нужен H.264 |
| `rtspt://` не работает | Порт 8554/TCP закрыт у провайдера |
| Часто подгружается | Поставьте `HLS_SEGMENT=2s` (и интервал ключевых кадров 2 с), снизьте битрейт |
| Большая задержка HLS | В OBS интервал ключевых кадров должен быть 1 с, а не «0/авто» |

## Что проверено

Скрипт проверен локально на MediaMTX v1.21.1: авторизация OBS (чужой ключ и анонимная публикация отклоняются), HLS (обычный плейлист без редиректов и cookie, сегменты по 1 с), RTSP только по TCP, RTMP, заставка при отключении и переподключении OBS. Сама установка на реальной VM и воспроизведение в VRChat локально не проверялись. После установки проверьте ссылки в VRChat на PC и Quest.
