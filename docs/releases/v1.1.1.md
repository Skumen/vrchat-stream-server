# v1.1.1 — исправлено «зависание» при ожидании обновлений на свежей VM
🔧 **Исправление.** Если вы ставите сервер на новую VM, используйте эту версию вместо 1.1.0 и 1.0.3.

## Что было не так

На Ubuntu постоянно работает служба `unattended-upgrade-shutdown --wait-for-signal`. Она ничего не устанавливает, а только ждёт выключения системы. Linux обрезает имена процессов до 15 символов, и у неё получается то же имя `unattended-upgr`, что и у настоящей установки обновлений.

Скрипт принимал эту службу за установку обновлений и ждал до лимита (15 минут), после чего завершался с ошибкой:

```
==> Система устанавливает обновления (apt занят: unattended-upgr) — жду…
==> …всё ещё жду: 2:30 (apt занят: unattended-upgr)
```

## Что исправлено

- **Установка обновлений определяется по полной командной строке** (`/usr/bin/unattended-upgrade`), а служба ожидания выключения больше не мешает.
- **Скрипт показывает, что делает dpkg** во время ожидания. Видно, что установка действительно идёт:
  ```
  ==> …всё ещё жду: 1:00 (apt занят: unattended-upgrade; dpkg: 16:40:01 unpack linux-firmware:all)
  ```
- **Регрессионный тест** на настоящих процессах: фальшивые `unattended-upgrade-shutdown` и `unattended-upgrade`. Проверяется в GitHub Actions на каждый push.
- **Надёжнее выпуск релизов:** заголовок и файлы проверяются после публикации. У 1.1.0 заголовок обрезался.

## Установка / обновление

```bash
curl -fsSL https://github.com/Skumen/vrchat-stream-server/releases/latest/download/setup.sh -o setup.sh
sudo DOMAIN=stream.example.com bash setup.sh
```

Если 1.1.0 уже установлена: `sudo vrc-stream update`. Ключ OBS, домен и остальные настройки сохранятся.

---

**English:** fixed a 15-minute hang on fresh Ubuntu VMs. The always-running `unattended-upgrade-shutdown --wait-for-signal` service shares the truncated process name `unattended-upgr` with a real upgrade run and was mistaken for one. Upgrades are now detected by the full command line, and the wait message shows the current dpkg action.
